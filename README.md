# 信仰游戏排行榜

AstrBot 群聊双积分排名插件：登神之路 + 觐见之梯双榜、职业信仰体系、道具储物与赠送、弃誓/立誓、群管指令，附带一套「神明在看」的沉浸感文案（位阶徽记、神明的赌局、祷词分档）。仅支持群聊。

## 功能特性

### 积分与榜单
- **双积分体系** — 登神之路 + 觐见之梯，双榜独立排名
- **榜单门槛** — 天梯榜默认只显示登神之路 ≥ 1100 分的玩家（`leaderboard_min_ladder_score`，0 为不过滤）
- **榜单缓存** — 结果缓存 `leaderboard_cache_seconds` 秒（默认 120，0 为不缓存）；任何录入/改分/改名操作都会立即失效对应群的缓存
- **批量录入** — 粘贴游戏结算文本自动解析，批量更新积分与道具（支持正负分、数量标记 `*10` / `（b）*10` 两种写法）
- **查询冷却** — 防刷机制，冷却时长可配置
- **直接回复** — 指令回复不经过 AI 处理，固定格式输出

### 玩家与道具
- **职业信仰** — 6 命途 × 16 具体信仰 × 96 具体职业，名片可自动识别
- **储物空间** — 道具名与等级分离（SSS/SS/S/A/B/C），支持赐予/收回/清除，按等级排序展示
- **赠送道具** — 玩家间赠送，发送方按 QQ 绑定鉴权（防名片冒充），接收方每日接受次数可配置，诸神代收不受限
- **玩家状态** — 自定义状态 + 持续天数，查询时显示剩余天数
- **弃誓系统** — 弃誓标记永久保留，排行榜显示 (弃誓者)，弃誓文本按信仰可配
- **群名片识别** — 查询/储物空间/赠送等指令自动从名片识别身份，职业词会被过滤

### 权限与管理
- **全局白名单** — 白名单一次添加所有群生效，可绑定具体信仰（诸神操作时显示对应神明文案）；名单只存在数据库里，用指令管理
- **管理员** — `admin_ids` 是**唯一**的管理权限来源；群主/群管理员不是管理员，他们只有诸神级权限（不能用白名单/同步白名单，也不能清空/重置本群数据）
- **入群待审** — 配了 `auto_whitelist_group` 后，入群者先进待审名单（**不授权**），要管理员用「白名单 通过 <QQ>」或「全部通过」确认才成为诸神；退群则自动撤销（待审记录一并清掉）。「同步白名单」同样只写待审，不直接授权
- **群访问控制** — `group_access_mode` 可选 off / blacklist / whitelist：未启用的群里插件**完全静默**（不回复、不抢事件），适合只服务指定群
- **功能开关** — 道具赠送、储物空间、祷词、排行榜、群管、祈愿试炼六块可单独关闭；诸神的录入与道具管理指令不受影响，避免管理员把自己锁死
- **状态阻断** — 状态可携带「禁止项」：`添加状态 张三 沉默 2 阻断=祷词,赠送`，被禁止的指令会回复提示
- **群管指令** — 禁言/解禁/踢人/撤回/全员禁/全员解/设置精华/移除精华（需 aiocqhttp 协议）
- **自动备份** — 每天自动备份数据库，保留天数可配置

### 沉浸感
- **神选？** — 觐见之梯榜首的名字前会多标一句「神选？」。原著里「神选」指觐见之梯中每个信仰排名第一的玩家，而玩家问出这句时本身就是疑问句，所以这里带了问号
- **祷告分档** — 祷词随机到区间上限时走「大成功」文案池，并显示「连续 N 天被你的恩主听见」（2/7/30 天三档）
- **位阶徽记** — 按登神之路分数分 9 阶，榜单与档案在名字前显示纯符号徽记（默认 ☽☿♀♁♂♃♄♅☉），不出现中文阶名
- **神明的赌局** — **默认关闭**（`wager_enabled`）：随机一位神明在群里抛出限时赌局，时限内「开口说话」或「献上祷词」即入局，开奖可能是兑现/嘲弄/嘴上反悔；**默认不影响真实分数**，`wager_score_enabled` 打开后只有「兑现」给赢家加分
- **祈愿试炼** — **默认不在任何群开启**（`wish_groups`）：凑满一队即自动「发车」，全员获得一条以队名命名的状态（默认 3 天）；到期之前名单可增删，状态严格跟随名单。名额按队名日期控制节奏（默认每周最多 6 次发车），详见「沉浸感系统 · 祈愿试炼（组队）」
- **状态来源** — 施加状态时写明由哪位神明降下、到哪天为止
- **祷词触发** — 玩家每天第一次发送命中自己命途的祷词时获得一次觐见分变化（默认命中 -2~+2、渎神 -2~0，区间可配）；默认只作氛围互动，`prayer_score_enabled` 打开才真实计分
- **储物空间彩蛋** — 可配置概率触发趣味消息

### 平台特性
- **合并转发** — 天梯榜、觐见榜、储物空间默认使用合并转发卡片展示
- **配置热生效** — 改 WebUI 配置后无需重载插件：祷词表、指令前缀、权限判定、榜单缓存都会跟着变
- **配置项全中文提示** — 80+ 个配置项每项都带 `hint` 说明取值与影响
- **指令名可定制显示** — `cmd_*` 影响帮助文案与祷词前缀过滤（指令本身在代码里注册，改名需改代码）

## 职业与信仰

### 层级结构
- **命途**（6）：虚无、存在、文明、沉沦、混沌、生命
- **信仰**（16）：诞育、繁荣、死亡、污堕、腐朽、湮灭、秩序、真理、战争、混乱、痴愚、沉默、记忆、时间、欺诈、命运
- **具体职业**（96）：每个信仰 × 6 普通职业，系统自动映射到对应命途和普通职业

### 普通职业
战士 / 法师 / 牧师 / 刺客 / 猎人 / 歌者

## 群名片自动识别

部分指令通过发送者的群名片自动识别玩家身份，无需手动输入名字：

- **查询**：非诸神用户直接发送 `查询` 即可查询自己；诸神用户需指定玩家名
- **查询储物空间**：非诸神用户直接发送 `查询储物空间` 查自己；诸神用户可指定多个玩家批量查询
- **赠送道具**：发送方按 QQ 绑定鉴权（需先绑定 QQ），格式为 `赠送道具 <接收方名> <道具名> [数量]`（数量也可写作 `道具*数量`）

非诸神用户指定其他玩家名不会生效，只会查询到自己的信息；指定他人需诸神权限。

### 名片解析规则

系统从群名片中提取所有非纯数字、非职业的词，逐个在数据库中匹配，返回第一个匹配到的玩家名。例如：
- `【命运】 织命师 蓬莱 1000 100` → 提取词：蓬莱 → 匹配数据库中的玩家名
- `【XX】 守墓人 张三 100 100` → 提取词：张三 → 匹配数据库中的玩家名

### 具体职业自动识别

名片中的具体职业（96个）会被自动识别并过滤，不会误匹配为玩家名。例如：
- `【湮灭】 烬灭者 蓬莱` → "烬灭者"是具体职业，被过滤；匹配"蓬莱"

## 白名单与权限

### 诸神权限
拥有白名单权限的用户可执行所有诸神指令。

### 白名单配置

白名单 add <QQ> [信仰]    — 添加诸神，可选绑定信仰（对已有诸神则更新信仰）

白名单 通过 <QQ>           — 通过一条入群申请，列入诸神

白名单 拒绝 <QQ>           — 丢弃一条入群申请
白名单 view               — 查看诸神列表

有信仰的诸神执行操作时，会显示对应神明的专属文案（如"【沉默】降下神赐"）。

## 沉浸感系统

原则是**数字反馈保持简单**：积分变更固定输出「+16 → 1016」的箭头样式（一眼能看出变化），氛围交给别处——榜单标记、位阶徽记、神明主题文案与赌局台词。

### 神选？

觐见之梯榜单的榜首，名字前会多标一句「神选？」：

```
═══ 觐见之梯 ═══

1. 神选？ 张三
   [法师] <生命>
   觐见之梯: 1150
   登神之路: 1010
```

原著里「神选」指觐见之梯中每个信仰排名第一的玩家，而玩家问出这句时本身就是疑问句（「你不会是【诞育】的【神选】吧？」），所以文案带了问号。

### 位阶徽记

按登神之路分数分 9 阶，榜单与玩家档案在名字前显示纯符号徽记（默认从低到高 `☽ ☿ ♀ ♁ ♂ ♃ ♄ ♅ ☉`），没有中文阶名：

```
═══ 登神之路 ═══

1. ☿ 张三
   [法师] <生命>
   登神之路: 1150
```

阈值与符号都是配置项（`tier_thresholds` / `tier_marks`），可整组换成 `✦Ⅰ…` 之类；符号配得比阈值少时，多出的阶层沿用最后一个。

### 神明的赌局

**默认关闭**。打开方式：`wager_enabled` = true，并在 `wager_groups` 填群号。之后每隔 `wager_interval_minutes`（默认 30 分钟）会有一位神明现身：

> 两个实现细节：① 插件必须**收到过该群的消息**才能开局（发消息需要完整会话标识，没见过消息时拿不到），所以在刚重载、群里还没人说话的空档里会跳过一轮，等有人说话后正常开局；② 间隔判定跨重载有效（用数据库里的上次开局时间兜底），不会因为重启就立刻冒出一场。

开局时刻：按 **UTC 时间等分**对齐（间隔 30 分钟 → 每小时 :00 与 :30；间隔 60 → 整点），再叠加每群随机的延后 0~`wager_jitter_minutes` 分钟（种子含绝对时间槽，**每天同一钟点的时刻都不同**）；同一时间槽内只开一局。**静默时段**（默认本地 0~8 点，`wager_quiet_start_hour` / `wager_quiet_end_hour`）里的槽直接跳过，夜里不会开局；全新安装会立刻开第一场（夜里则等到白天）。

开局条件（自动）：总开关打开 · 群在 `wager_groups` 里 · 群**未被群访问控制排除**（黑名单/白名单模式都会生效）· 当前没有进行中的赌局 · 距上次开局已过 `wager_interval_minutes`。**也可以手动开局**：诸神/管理员在群里发送 `赌局` 即可立刻开始（不看群列表与间隔，其余条件相同；已有赌局进行中会提示还剩多久）。

```
【欺诈】眯起眼睛：「60 秒内，开口说话的人——我给他一点甜头。当然，我说的是不是真话，你得自己赌。」
```

时限内完成指定动作（开局时随机要求「开口说话」或「献上祷词」——**只有在开着祷词触发的群里才会抽到「献上祷词」**，否则只会要求开口说话）即入局，时限到开奖，结果三分：**兑现 / 嘲弄 / 嘴上反悔**。默认只发文案并注明「本次结果不影响实际分数」；`wager_score_enabled` 打开后只有「兑现」会给赢家加 `wager_reward` 点觐见分。**神明可以在台词里骗你，但绝不会真的动你的分数或道具。**

每场赌局只产生两条群消息（开局 + 开奖），参与者上限 200 人，开局与入局记录在 `god_wagers` / `god_wager_entries` 两张表。16 位神明 × 5 档（开局/兑现/嘲弄/反悔/无人入局）共 80+ 句默认台词，可在 `wager_messages_*` 里整体替换（按神明覆盖用 `wager_messages_announce_欺诈` 这种形式）。

### 祈愿试炼（组队）

**默认不在任何群开启**：在 `wish_groups` 填群号才生效。玩法是一句话：**凑满人，一起被记住三天**。

`祈愿组队 [人数]` 开一支队伍（开团者自动入座），`祈愿加入` 补上最缺人的一支，满员即自动「发车」：每位成员获得一条**以队名命名的状态**，持续 `wish_status_days`（默认 3 天）。状态出现在「查询」里，例如 `09月28日祈愿试炼: 剩余3天`。**除此之外没有任何数值产出**——不发分、不发道具（没有产出就没有得刷的东西）。

队名由系统生成，格式是 `队名日期 + 祈愿试炼`，而日期是**开团日 + 状态天数**，即这条状态到期的日子。玩家不能自取队名（`祈愿组队` 只收一个人数参数），只有诸神能用 `祈愿管理 重命名` 改。

**3 天窗口内名单是活的。** 发车不是终点：在状态到期之前，名单可以增删，状态严格跟着名单走——

| 操作 | 名单 | 状态 |
|------|------|------|
| 满员发车 | 保持 | 给全员按**队伍的到期时间**挂上 |
| 有人补位（`祈愿加入`，任何人的空位都能填） | +1 | 给新人挂上，**与队友同一天到期** |
| `祈愿管理 移出 <队名> <玩家名>` | −1 | 撤销该玩家的状态 |
| `祈愿管理 换人 <玩家1> <玩家2>` | 一出一进 | 撤销玩家1 的，把同一个状态（同名、同到期）转给玩家2 |
| `祈愿管理 解散` | 整队 | 撤销全队状态 |
| `祈愿管理 延期 <队名> <天数>` | 保持 | 改**队伍**的到期时间，全队状态同步（只延不缩） |

所以「到期时间」这件事只有一个事实来源：队伍。补位进来的人不会比队友晚一天到期，延期也是全队一起延。**退群**的人会被自动移出（需要该玩家已绑定 QQ；未绑定的只能等超时回收），腾出的空位任何人都能补。

#### 名额：每天一场

节奏靠**名额**控制。名额既不看今天、也不看发车日，而是看**队名里那个日期**（= 开团日 + 状态天数）的星期——它管的是「状态什么时候到期」。默认表 `wish_weekly_limits = [1,1,0,1,1,0,2]`（按队名日期的星期索引，周一…周日）：

| 开团日 | 队名日期（+3 天） | 名额 |
|--------|------------------|------|
| 周一 | 周四 | 1 支 |
| 周二 | 周五 | 1 支 |
| **周三** | 周六 | **0（不能开团）** |
| 周四 | 周日 | 2 支 |
| 周五 | 周一 | 1 支 |
| 周六 | 周二 | 1 支 |
| **周日** | 周三 | **0（不能开团）** |

也就是**每周最多 6 次成功发车**。实际效果是「周三与周日不能开团」，而不是「周三周六」——中间隔了 3 天，这一点容易看错，改 `wish_status_days` 还会让整张表跟着平移。

名额**只有成功发车才消耗**：开团不占名额，所以可以同时有两支队在招募（`wish_list_limit` 默认 2，它同时是「本群招募中队伍数上限」与大厅展示上限，因此**不会出现大厅里看不见的队伍**）。名额为 0 或已用尽时，开团与加入都会被直接劝退，而不是让人白等一场；某队发车把该日期的名额用尽后，同日其余还在招募的队伍会被立刻判为「未能成行」并播报。

#### 其他约束

- **每人每天开团 1 次**（`wish_daily_create_limit`）、**每群每天开团 4 次**（`wish_daily_group_create_limit`）。被前置检查（关闭日、名额不足、已有队伍、群内队伍已满）拒绝的开团**不消耗**这些次数。
- **同一玩家同一名额日期只能参与一次**；同时只能在一支进行中的队伍里。
- **身上已有同名状态时不能加入同名队伍**（默认队名带日期，通常只在诸神改名后才会撞上）；提示会给出三条出路（换队 / 等过期 / 请诸神 `重命名状态`）。
- 招募等待 `wish_disband_minutes`（默认 45 分钟），每隔 `wish_reminder_minutes`（默认 15 分钟）在群里催一次缺人提醒，超时自动解散（空队不播报）。**开团时就把「上次提醒」记成开团时间**，所以开团播报之后不会马上又冒一条提醒。
- 已结束的队伍记录保留 `wish_history_retention_days`（默认 7 天），`祈愿管理 已解散` 只看得到保留期内的。**同一玩家最多保留 `wish_status_keep`（默认 3）条队伍状态**，超出的按到期时间从早到晚裁掉。
- **`祈愿管理` 是诸神级权限**（超管 ∪ 白名单诸神 ∪ 本群群主/群管），比「天梯榜管理」宽——按设计要求，队伍治理交给诸神。功能开关关掉或群从 `wish_groups` 移除后，`祈愿管理` 仍可用，以便收拾遗留队伍。

#### 接上既有的录分流程

`祈愿管理 名单 <队名> [登神分] [觐见分]`：不给分数就列出队员名；给了分数则输出**可以直接粘贴进「批量录入」的文本**（每个成员一块 `【玩家：甲】【登神之路+16】【觐见之梯+2】`）。诸神办完试炼只需要填两个数字，不必手写 6 个块——分数仍由诸神决定，功能不替他做决定。

> 两个实现细节：① **跨天发车会有一天误差**——每天 23:15 之后开团，发车会跨到第二天，此时队名里的日期（开团日 +3）比状态实际到期日（发车日 +3）早一天；② 开团、发车、换人、超时解散都会往群里播报，消息量由「每群每天 4 次」兜底，跑一段时间后按实际噪音调这个数。

## 术语来源：哪些跟了原文，哪些没有

v3.7.10 做过一轮「文案对齐小说《诸神愚戏》原文」的改造。为免后人把这些当成漏改，这里把**有意保留**和**属于插件自造**的词一次列清。原文用词的出处（行号）都记在 `terms.py` 里。

| 词 | 状态 | 说明 |
|---|---|---|
| 登神之路 / 觐见之梯 | 原文，保留不动 | 榜单名沿用原文 |
| 命途 / 信仰 / 职业 / 弃誓 / 棋盘 | 原文，保留不动 | 「祂们打造了这座棋盘」见原著第 50812 行；弃誓在原著出现 132 次 |
| 恩主 | 原文，限定使用 | 只指「玩家自己所奉的那位神」。泛指神明处一律用「神明 / 诸神」——系统播报、状态降下、管理指令都不套这个词 |
| 神选？ | 原文词，借用 | 原著的神选是**每个信仰各一名**；本插件标的是全命途混排觐见榜的榜首，语义有出入，靠问号弱化 |
| 储物空间 | **有意保留** | 原文 146 次用的是「随身空间」，「储物」只出现 3 次。此处按插件既有叫法保留 |
| 位阶徽记 | **插件自造** | 原著里「位阶」指神明与半神器的位阶，拿来给玩家分阶是借用 |
| 诸神列表 / 白名单 | **插件自造** | 管理员名单是插件概念，原著没有对应说法（「列表 / 名录 / 名册」在原著合计出现 0 次），保持中立措辞 |
| 3 条祷词 | **插件自拟** | `prayer_text_诞育`、`_湮灭`、`_沉默` 三句在原著找不到对应整句，其余 13 条可以 |

| `wish_default_capacity` | int | 6 | 未指定人数时的默认队伍人数（玩家唯一能定的参数） |

## 版本

最近几个版本（更早的见 [CHANGELOG.md](CHANGELOG.md)）：

- **v3.9.0** — 新增**祈愿试炼（组队）**：`祈愿组队 [人数]` 开队、满员自动「发车」，全员获得一条**以队名命名的状态**（默认 3 天）；到期之前名单可增删，状态严格跟随名单（移出/解散撤销、补位/换人按队伍到期时间挂上）。名额按队名日期（= 开团日 + 状态天数）的星期控制节奏，默认**每周最多 6 次发车**（实际关闭的是周三与周日）；**默认不在任何群启用**，在 `wish_groups` 填群号才生效。诸神侧新增 `祈愿管理`（列表/已解散/名单/换人/解散/重命名/移出/补位/延期/清空），其中 `名单` 可输出**直接粘进「批量录入」**的文本；同时新增 `重命名状态`（改状态名，目标名已存在则合并），`player_statuses` 增加 `source` 列以区分队伍状态与诸神手工状态
